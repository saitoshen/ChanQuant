# CTP（openctp-ctp）：只有 Windows / Linux x86-64 的 wheel，macOS 上装不了。
# 写进这里会让 macOS 的 `pip install -r requirements.txt` 直接失败，三平台构建
# 就废了。要接 CTP 时手动装：
#
#     pip install openctp-ctp          # Windows
#
# 没装也不影响任何其他功能 —— `ttrade/ctp_client.py` 用 try/except 导入，
# `--selftest` 会照实报「openctp-ctp 未安装」。CI 里也是一步独立的、
# `continue-on-error` 的 Windows 专属安装。
#
# 融航资管中台（vnpy_rohon）：只有 Windows x86-64 的 wheel，且只有
# cp310 / cp313 两个 ABI（本机 base 是 3.14 ⇒ 装不上，`envs/fq` 是 3.13 ⇒ 能用）。
# 三个硬约束，少一个就会踩坑：
#
#   1. **必须 `--no-deps`**。它的依赖表里写着 `vnpy>=4.0.0`，而 vnpy 4.5 把
#      `pyside6==6.8.2.1` 钉成硬依赖 —— 一装就把本程序的 pyside6 6.11
#      降级，界面当场变形/起不来。我们只借它的 `vnpy_rohon.api` 驱动层
#      （两个 .pyd + 四个 dll + 常量表），那一层根本不 import vnpy。
#   2. 装完**不要**再 `pip install vnpy`，也不要让它被别的包顺带拉进来
#      （`pip check` 会因此报一条 vnpy 未满足，属预期，忽略）。
#   3. 版本钉死 6.7.2.5：它是按当前融航客户端 6.4.x 的 API 编的，换版本
#      要重测（`RohonHub.check_deps()` 里写的也是这个号）。
#
#     pip install vnpy_rohon==6.7.2.5 --no-deps      # Windows + cp313
#
# 没装时 `ttrade/rohon_client.py` 的 `HAS_ROHON` 为 False，界面里融航账户
# 一勾就提示装包，其余功能（含 CTP / 天勤）完全不受影响；`--selftest`
# 里有一项专门检查这种「未装时也照实报错、不炸」的行为。
