# 写一份品种研报

研报和聊天回答的区别只有一个：**每个判断后面要跟一个数字**。
「库存偏高」不是研报，「仓单 57,225 吨，五年同期 82 分位」才是。

## 第一步：先拿事实包，不要自己翻数据

```
report_pack(symbol="RB_SHFE")
```

一次拿到八组东西：价格状态、月度季节性、基本面（仓单/库存/现货价/利润/交割量）、
现货基差、期限结构、因子 IC、策略对比、宏观分位、板块动量。

**为什么必须用它**：这些数各自要不同的接口和口径，一条条问要七八轮，中间还会漏。
事实包里的数字都带口径（多少年、什么窗口、秩相关还是皮尔逊），
写进报告时**原样带上**，否则读者没法复核。

事实包里没有的（产量、进口、政策、开工率），用 `web_search` 找；
找不到就写「未接入」。**编一个数比留空糟糕得多** —— 研报是要被人拿去做决策的。

## 第二步：出图，四张就够

```
chart(kind="price_seasonality", symbol="RB_SHFE")
```

| kind | 说明什么 |
|---|---|
| `price_seasonality` | 哪几个月涨、涨的概率多大 |
| `inventory_seasonality` | 库存的季节性拐点（累库/去库节奏） |
| `big_swings` | 历史波段复盘：涨了多少、用了多久 |
| `factor_ic` | 哪些因子在这个品种上真的有效 |
| `term_structure` | 曲线是 backwardation 还是 contango |
| `vol_regime` | 现在是趋势还是震荡 |

不要六张全上。图多不显得专业，只显得没重点 —— **每张图后面必须有一句它证明了什么**。

插图写法：图片**独占一行**，`![说明](路径)`，混在段落里排版会乱。

## 第三步：按这个顺序写

1. **一句话结论** —— 方向、周期、什么条件下推翻它。写不出「什么条件下推翻」，
   说明你其实没有结论
2. **价格状态** —— 20/60/120 日收益、波动分位、效率比（≥0.30 趋势 / <0.15 震荡）
3. **季节性** —— 强弱月份 + 上涨概率，配 `price_seasonality`
4. **基本面** —— 仓单、库存、基差、利润、交割量，配 `inventory_seasonality`
5. **期限结构** —— 展期收益率正负意味着什么
6. **因子 IC/IR** —— 只写 |IC| 排前面的那几个，并说明 IR 是否稳定
7. **策略对比** —— 买入持有是基准。跑不赢它，说明赚的是 beta 不是择时
8. **历史波段复盘** —— 挑 2–3 段，说清驱动是什么
9. **未来波段推演** —— 给条件（「若仓单继续去化且基差转正」），不给点位
10. **适合的因子与策略** —— 具体到因子名和策略名，以及失效信号

## 三个最容易犯的错

**把相关当因果。** 「库存下降，所以看涨」——库存下降可能是需求好，也可能是
贸易商囤货。要写「库存下降**且**基差走强」这种两条腿都站得住的组合。

**用水平值代替分位。** 利率 2.5% 在 2019 年是常态，在 2023 年是低位。
宏观数据一律说分位（0% 历史最低 / 100% 最高），不说绝对值。

**忽略基准。** 任何策略的年化都要和买入持有比。牛市里随便一个多头策略都好看。

## 第四步：导出 PDF

报告写完后落盘成 `.md`，导出走 `write_pdf`（或研报库里的 PDF 按钮）。
图片会在导出时读成 base64 内联 —— 报告目录挪到别的机器上图片就没了，
**要带走就连图一起带**。
