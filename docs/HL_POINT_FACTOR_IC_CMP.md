## 一、口径怎么对齐的

原项目的锚点是 `strategy/hl_point/tools_factor_report.py::ic_ir()`。本对照**照抄**这套口径：

| 项 | 原项目 | 本机 |
|---|---|---|
| 周期 | `HL_ML_TF=1h` | `tqdata.load_main(..., "1h")` |
| 截面 | **日盘快照**：只留 `8<=hour<16`，对 (日历日, 品种) 取**最后一根** | 完全照抄 `snap_positions()` |
| 步长 | 每 **5 个交易日**一次截面 | 同 |
| 标签 | 未来 `H = 5×6 = 30` 根**原始收益** | 给两档：`H=30`（根数一致）/ `H=46`（5 天 × 实测 9.28 根/天，**经济期限一致**） |
| IC | 截面 `Spearman(factor, y)` 的序列均值 | 同 |
| 样本 | 77 品种（69 商品 + 8 金融），n≈486~495 | **69 个商品**，n≈477 |
| 因子函数 | `indicators.build_features` + `levels.level_features` + `_oi_features` + 展期面板 | `ttrade/factors_hlpoint.py`（33 新 + 3 映射） |

两档持有期是刻意的：原项目 `BPD=6` 是拍的（本机实测 **9.28 根/天**，夜盘比原项目设想的长），
所以 `H=30` 比的是「根数」，`H=46` 比的是「5 个交易日」。**两档结论一致，下面只讲 H=46。**

## 四、三段归因：把「函数」和「数据」分开

做了 2×2：同一个 IC 管线，分别换函数、换数据。

| 对照 | 换的是什么 | 秩相关 | 同号 | 结论 |
|---|---|---|---|---|
| 原报表 vs **原fn** | 只换数据（原因数不变） | **+0.17 / +0.38**（H30/H46） | 16/29、20/29 | 数据差异就能把 IC 打散 |
| 原fn vs **CQ** | 只换函数（同一份本机数据） | **+0.84 / +0.86** | 33/36、35/36 | **因子实现基本等价** |

**逐条看「原fn − CQ」：32 个价格/持仓量因子的差值全部 ≤ 0.001**（表里 `ΔIC_原函数vsCQ` 一列），
说明 `ttrade/factors_hlpoint.py` 的移植是准的。真正不一样的只有 4 条，各有各的原因：

### 1. 🔴 `roll` / `roll_ann`：**不是复权改坏了因子，是复权改了标签**

⚠️ **先纠正一个容易说错的点**（用户 11-24 指出）：展期因子是**真实合约**算出来的
（`o6_1/2/3_close` 那几条腿的盘面价，或原项目的 `contracts` 表），**和 888 主连复权无关**。
实测（`_tools/hlpoint_revadj_probe.py`，24 个主力，2016-01~2026-10）：

| 因子 | qfq vs 不复权，逐品种 max\|Δ\| |
|---|---|
| `roll_main_oi` | **0.000e+00**（逐位相同） |
| `roll_main_annual` | **0.000e+00** |
| `dist_hi`（主连 OHLC 算的） | 1.2e+08 |
| `dev_z_60`（主连 OHLC 算的） | 7.54 |

所以两次加载**因子值一个字节都没变**，翻号的是 **`y`**。把 `y` 拆成两截直接看：

```
y_raw = 不复权主连的 h 根收益
y_qfq = 复权主连的 h 根收益        （本库现状）
y_gap = y_raw − y_qfq              （换月跳空那一截，其余时候 = 0）
```

| 因子 | IC vs `y_qfq` | IC vs `y_raw` | IC vs **`y_gap`** |
|---|---|---|---|
| `roll_main_oi` | **+0.0412 (t 2.88)** | **−0.0192 (t −1.30)** | **−0.1330 (t −11.35)** |
| `roll_main_annual` | +0.0441 (t 3.07) | −0.0229 (t −1.55) | **−0.1480 (t −12.33)** |
| `dist_hi` | −0.0155 (t −1.19) | −0.0376 (t −2.93) | −0.0249 (t −2.41) |
| `dev_z_60` | −0.0107 (t −0.86) | −0.0140 (t −1.11) | +0.0053 (t 0.50) |

- 换月窗口占 **11.6%**（6629/57147），`y_gap` 非零占 **13.4%**，`|y_gap|` 均值 **0.283%**；
- carry 与「换月跳空」的负相关 **t = −11 ~ −12**，比它和任何一种真实收益的关系都强一个数量级。

**机制**：back 结构（`roll>0`，近月 > 远月）的品种，主连换成远月那一下价格要往下跳，
**跳幅 ≈ 日历价差** ⇒ 「carry 高」和「接下来要跳空亏钱」是同一件事的两面。

### 1b. 🔴 那原项目 1h 到底复没复权？——**声称 v2，实际没复权**

这一条必须钉死，因为它决定了「−0.026 该跟谁比」：

| 层面 | 事实 |
|---|---|
| 代码意图 | 所有入口都写 `adj='v2'`（`load_bars` 默认值、`tools_ml.build_panel`、`engine.backtest_symbol`、`tools_hl_xsig`） |
| `data_feed` 头注释 | 「主力换月**后复权**（默认 v2）…否则会凭空造出假高点/假低点，直接污染本策略的核心结构」 |
| **实际行为** | **1h/30m/15m 全部没复权** |

证据（`_tools/hlpoint_v2adj_probe.py`，RB/CU/M/TA/I/AU 六品种，2019-01~2026-10）：

- `load_bars(sym,"1h",adj="v2")` 与 `adj=None` 的收盘价比值 **恒为 1.000**；
  `|Δ收益|` 均值 **0.000%**、非零占比 **0.0%**；返回里**没有 `adj_factor` 列**；
- 代码上：`apply_adjust` 在 `data_feed.py` 里**只出现两处**（定义 + `load_daily_raw` 第 312 行调用）；
  1h 分支是 `load_minute_raw` → `resample_session` → 直接返回，**从不调用 `apply_adjust`**；
  `adj` 在那个分支里**只进了缓存 key**（`extra=f'{adj}_sess2_{CACHE_VER}'`）—— 看起来像复权了，其实没有。

⇒ **原项目 `HL_ML_TF=1h` 的全部结论（因子 IC、WF 回测、PIT 回测）都建立在「不复权 888」上**，
但这不是它选的口径，是一个漏实现的 bug（只有 `1d` 真复权）。

**两层含义**（别混）：

1. **要逐字复现原项目的数字，本库必须 `adjust=None`** —— 原项目 −0.026 落在「不复权 y」的区间
   （−0.019 ~ −0.035），本库 qfq 给 +0.02 ~ +0.04。⚠️ 但这等于**复现一个 bug**：
   1h 上 250 根高低点被换月跳空污染，正是 `data_feed` 头注释警告的那件事。
2. 🔴 **不能把「原项目 roll IC −0.026」当成 carry 有预测力的证据** —— 它预测的是
   **换月日历**，不是行情。不复权口径下持 888 跨换月**真的要付**这个跳空，所以把跳空算进
   回测收益是对的；但它同时会教模型「快到换月了就降 carry 敞口」，那是**执行成本规避**，不是 alpha。
   要做「carry 是否预测涨跌」的研究，得先把 `y_gap` 剔掉再算。

`dist_hi` 属于**两头都被复权影响**的那类：因子本身用主连 OHLC（复权后 250 根高/低不同），
`y` 也带着跳空 ⇒ qfq −0.0155 / 不复权 −0.0376 / 原报表 −0.0259 夹在中间。

### 2. 🔴 `roll_main_curv`：库里公式**符号相反**

同数据下原函数 **−0.0197**（和原报表 −0.0283 同号）、CQ **+0.0276** —— 只有这一条在「同数据换函数」里
差得离谱（Δ 0.047）。原因是公式本身：

- 原项目：`curv = ln(P_far/P_mid) − ln(P_mid/P_near)`（**近端斜率 − 远端斜率**）
- 库里 `factors.py::_roll_main_raw`：`curv = (l2/gap2 − l1/gap1) × 365`，其中 `l1=ln(near/mid)`、`l2=ln(mid/far)`
- 展开后 **`curv_库 = −(curv_原) / gap × 365`**，等间隔下严格差一个负号（外加年化缩放）

附带一个文档自相矛盾：库里 docstring 写「曲率为负＝近端更陡」，但按上面的推导，
近端更陡对应 `curv_库 > 0`。**方向和说明是反的**，看这条因子时别按注释读。

### 3. `roll_chg_20`：组合差异（Δ −0.016）

库里差分的是**价差率**且先做了 5 日均值、没有 `shift(1)`；原项目是 `roll − roll.shift(20)` 之后整体
`shift(1)`（用上一交易日）。两处叠加导致差 0.016。量级不大，但同号。

### 4. 关卡族 4 条：原报表 IC 是 NaN

`clus_high / clus_low / level_high / level_low` 在原报表里 IC 全 NaN —— 说明原项目在多数快照上这几列**是常数**
（Spearman 无定义）。本机这四条都有 0.006~0.011 的 IC，含义是**实现产生的变化程度不同**（不是方向问题）。
这四条在原项目的 LightGBM 里 gain 加起来只有 1.3%，影响很小，但要知道它不是「复现失败」。

## 五、结论

1. **因子实现没问题**：32 个价格/持仓量因子在同数据下逐条差 ≤ 0.001，秩相关 0.86、同号 35/36。
   `factors_hlpoint.py` 的移植可以放心用。
2. **逐因子 IC 不是可靠的验收锚**：36 个因子里原项目 11 个 `|t|>2`、本机 8 个，但**排序和符号都对不上**
   （秩相关 +0.02）。原因有两层：
   - 这些 IC 本身就在 1~3σ 的噪声区（`|IC| ≈ 0.011`，截面 490 个、IC 标准差 0.19，SE ≈ 0.009）；
   - 换一份数据（同函数）秩相关就只剩 0.17~0.38 —— **IC 的抽样波动比「平台差异」大**。
   ⇒ 验收要看**合成分数 IC / 组合绩效**，别逐条对单因子 IC。
3. **数据侧有一条真差异：复权口径 —— 但它改的是 `y`，不是展期因子值**。
   `roll_*` 两次加载（qfq / 不复权）结果**逐位相同**（max|Δ| = 0），翻号来自 `y`：
   不复权主连在换月时跳空，跳幅 = 展期价差 ⇒ `IC(roll, y_gap) = −0.133 (t −11.4)`，
   而 `IC(roll, y_qfq) = +0.041`、`IC(roll, y_raw) = −0.019`（原报表 −0.026 落在后者区间）。
   用主连 OHLC 算的那批因子（`dist_hi` / `dev_z_60` / `shadow_*`）则是**因子和标签两头都被影响**。
   🔴 补充（1b）：原项目**声称** `adj='v2'` 后复权，但 1h 路径**从不调用 `apply_adjust`**，
   实测 `adj='v2'` 与 `adj=None` 价格恒等 ⇒ **它 1h 全链路是不复权的**，这是个漏实现的 bug。
   ⚠️ 所以「原项目 carry IC −0.026」不能当成 carry 有预测力的证据，它测的是换月日历。
4. **一条真实现差异：`curv` 符号相反**（外加注释写反）。
5. 🔴 **2026-11-24 补（原项目侧已修并回测，见 `future_quant/reports/HL_POINT_1h_真复权修复_20261124.md`）**：
   把 1h 真复权做上之后，原项目「十分位多空 期均 +0.941% / t +4.32 / 夏普 +1.74」掉到
   **+0.127% / t 0.75 / 夏普 0.30**。归因极干净：同一份旧预测对含跳空的 `y` IC +0.0431，
   对干净 `y` 只剩 **+0.0070**；按窗口内是否碰换月分组，**不碰换月的那 86% 样本 IC 只有 +0.0044**
   —— 也就是说那 0.94%/期 的「alpha」有 87% 就是换月跳空。
   ⇒ 结论 3 里那句「不复权的 `y` 含换月跳空 = 真实持仓成本」要修正：**它不是持仓成本，
   是 888 指数的记账假象**（跨月是卖旧买新，仓位价值从新合约接着走）。
   顺带发现第二个 bug：v2 因子边界会错位（SA 晚 4 个交易日、FG 晚一根），
   在平静日凭空造出 13~19% 的假跳空，已用「888 观测跳变校准」修好。
